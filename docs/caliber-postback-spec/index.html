Caliber Postback Spec

Endpoints

Transfer Fires on transfer connection to the buyer https://quhxbgsgtfvrasyjvaba.supabase.co/functions/v1/postback-transfer-webhook
Monetize Fires when the call converts and revenue is known https://quhxbgsgtfvrasyjvaba.supabase.co/functions/v1/postback-monetize-webhook

Set these up for every offer except Internet, which keeps its current postback. Fire both for a call that transfers and converts. The endpoint sets the event type. GET with query parameters or POST (JSON or form) both work.

Read these first

Secret: sent to you separately

Send it in an x-webhook-secret header (preferred), or as secret=<secret> in the URL if your platform cannot set headers. A missing or wrong secret returns HTTP 401.

Unknown parameters are ignored, not rejected

Extra parameters never cause an error. Response codes once the secret is accepted:

200 stored, or a re-fire of a call we already have — do not retry. 422 a must-have field is missing or wrong — fix it and fire again. 503 we could not save it — retry.

publisher must be exactly NBA

Hard-code publisher=NBA in the URL, as shown below. Any other value is rejected with HTTP 422.

caller_id is required

The caller's own phone, E.164 (+15551234567) — the number they call from, not the number they dialled. Missing or fewer than 10 digits is rejected with HTTP 422.

caliber_call_id is required

The Caliber call id: Caliber's own id for the call, set when CallTools transfers the call to Caliber and sends the data. Send the same id on the transfer and the monetize postback for one call. Missing is rejected with HTTP 422.

call_id is the CallTools call id

CallTools gives every call an id when the call starts. Send that id in call_id. Do not put the Caliber call id in call_id. A missing call_id is not rejected, but send it on every call.

conversion_time comes from the current call

Never a time from a prior call.

Transfer: the time the call was transfer-connected to the buyer.

Monetize: the time the call converted; the call end time is next best, and transfer time next after that.

Send tokens resolved

If a field has no value, send the parameter empty — not [tag:User:gclid], for example.

A rejected postback returns every problem at once:

HTTP 422 response
{"ok":false,"stored":false,"error":"missing_or_invalid_required_fields",
 "errors":[{"field":"caller_id","problem":"missing or fewer than 10 digits"},
           {"field":"caliber_call_id","problem":"missing: send the Caliber call id"}]}

3 · Counting rules

One row per real call event

Every transfer postback is a countable transfer, and every monetize postback is a countable conversion. Two calls from the same caller on the same day both count. We key on caliber_call_id only so that an accidental re-fire of the same call is ignored.

Do not fire on “no connect”

If the call does not connect, do not fire. As a safety net we also drop any event whose call status contains “no connect”.

4 · How to test

Fire one of each against the URLs above with real values and the secret. Expect HTTP 200 with a body like:

Example response
{"ok":true,"event_id":"<uuid>","inserted":true,"status":"transfer_ready",
 "event_type":"call_transferred","cv_source":"caliber","offer":"cpn_ene",
 "matched_by":"transaction_id"}
  • HTTP 401 — the secret did not arrive or is wrong. Check the header name is exactly x-webhook-secret.
  • HTTP 422 — a must-have field is missing or wrong; errors names each one. Nothing was stored.
  • HTTP 503 — we could not save it. Fire it again; a repeat of a call we already saved is ignored.
  • stored:false with skipped — a no-connect call, not stored by design.
  • inserted:false — we already had this caliber_call_id for this event, so we treated it as a re-fire.
  • cv_source:"caliber" — your cv_source arrived. ringba means it did not.
  • offer — your campaign value, stored in lower case. null means it did not arrive.
  • event_type — call_transferred or call_converted_revenue; it must match the endpoint you called.
  • matched_by — how we joined to the lead: transaction_id is ideal, caller_id is the phone fallback, null means no lead matched.

Send us the caliber_call_id of your first test call and we will confirm every field landed.
